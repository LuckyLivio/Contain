## 本轮改变

Contain 的普通用户入口迁移为真实 WPF 桌面应用，仍运行 `Contain.Viewer.exe`。
本轮围绕“记录安装 → 找回记录 → 查看文件操作及依据”整理页面与交互：

- **我的记录**：优先展示名称、时间和记录状态；同名记录有可见区分，实际查询
  始终绑定准确会话 ID。首次空库显示创建入口，外部库明确标为只读。
- **新建记录**：选择 EXE 后再明确点击“开始记录”；名称自动建议，默认跟随
  安装器及已有规则支持的已验证直接子进程，保存到“我的记录”。高级配置折叠
  保留，运行时显示真实阶段、任务耗时、可用进展和失败原因。
- **记录详情**：分别说明安装器退出结果、记录保存和覆盖限制；文件操作、状态
  对比和技术依据分区。事件解释先给简明中文，仍可查看原始操作、完整路径、
  事件 ID、原始 JSON 和依据。
- 统一浅色主题、紧凑导航、青绿强调色、系统 UI 字体与 Fluent 风格图标。
  WPF UI 提供窗口、标题栏、导航、按钮及对话框，Contain 实现任务生命周期、
  客户端接入、会话一致性和证据展示。

这次迁移没有增加卸载、删除残留、回滚、路径知识库或后台常驻采集，也没有重写
ETW、归因算法、CLI 协议或 SQLite schema。Beta.10 继续作为独立回退版本，
其[既有标签与附件](https://github.com/LuckyLivio/Contain/releases/tag/v0.3.2-beta.10)
保持不变；新包只有一个普通用户主入口。

## 最短使用步骤

1. 下载最终发布的 Windows x64 ZIP，**完整解压**，运行 `Contain.Viewer.exe`。
   自包含包无需用户另装 .NET、Rust、Visual Studio 或 Python。
2. 进入“新建记录”，选择已有 EXE，再点击“开始记录”。选择文件本身不会
   启动安装器；普通流程无需选择数据库、猜测安装目录或展开高级设置。
3. 按安装器要求完成操作，保持 Contain 窗口打开，等待采集、整理和保存结束。
   环境或来源不可用时按当前页说明处理；程序不会自动提权或偷偷改成快照模式。
4. 保存确认后查看本次准确记录，在“文件操作”中搜索目标文件、选择事件查看
   解释，需要时复制事件 ID 或导出报告。再次打开程序，从“我的记录”找回。

原个人库位置仍由 Windows LocalApplicationData 确定，保持
`Contain\Records\contain.db`，不随 ZIP 位置或启动工作目录变化，不重建已有
个人库。外部记录库通过现有客户端只读打开，不修改原库，也不改变新记录的默认
保存位置。随包 `samples/viewer-demo.db` 明确是合成演示数据，不是真实安装记录。

## 保留的功能与证据含义

搜索仍由核心覆盖当前会话全部事件，界面每页最多 50 条，不先把全部事件加载到
前端筛选。修改搜索、切换会话或选择事件会取消或拒绝过期结果，旧错误不能覆盖
新选择。查询、解释、复制和导出使用同一会话与事件身份，不依赖同名记录、最新
记录或任意 UUID 替代。

“导出本页报告”保留普通浏览页、所选解释和本记录状态变化的范围；搜索时
“导出全部 N 条匹配结果”固定开始时的会话、查询、完整内容标识和排序。既有
130 条事件 / 53 条匹配样例用于核对两页搜索、准确 ID、顺序和完整导出。
选择保存对话框之前即固定导出上下文，取消、失败或目标已存在不能变成成功覆盖。

名称可直接修改；高级设置保留手动观察已有目录、自定义保存位置、每行一个字面参数、HKCU
注册表、显式快照模式、静默等待和最长排空时间；沿用原验证、互斥与资源上限。
关闭活动任务不会误杀安装器。结束后关闭窗口先取消只读查询与导出，并等待其
句柄和临时文件清理；清理超时会显示失败并保持窗口。

以下事实继续分别表达：

- 安装器退出码 0 不证明最终安装状态已验证，保存成功不证明覆盖完整。
- `Unknown` 表示证据不足，不表示危险；`High` 表示有依据的执行进程关联，
  不证明最终文件所有权，也不是安全删除许可。
- 默认跟随模式没有安装前基线，不能用“新增文件 0 个”暗示没有操作。
  未提供统计、没有基线和实际零值各自表达。
- 历史缓存名称不是已验证的当前路径。损失后的升级抑制、来源与身份要求不变。
- 接收、候选、线程间交付和原始保存损失按既有口径分项，不重复求和。已结束且
  读回成功但存在丢失时明确显示“记录已保存；采集期间丢失了部分记录”。

详细功能对应关系见[迁移清单](beta04-design-and-migration.md)。

## 继续保留的已知问题和限制

  空库 Ready 超时原因尚未确认。
- [#17](https://github.com/LuckyLivio/Contain/issues/17)：Beta.10 的 D5 安装
  结果观察阶段控件缺失原因尚未确认。
- [#18](https://github.com/LuckyLivio/Contain/issues/18)：用户 Parallels 原始
  会话的 57,767 条应用丢失尚无原机分项，根因未确认。

本轮另保留 M11 的一次隔离导航控件键盘检查超时：M12 分阶段诊断未复现，原因尚未确认，不能称为产品键盘问题已修复。M13 最终包已独立通过实际键盘和完整桌面流程。

本轮界面迁移不追认以上历史原因，也不把它们描述为已修复。新 WPF 迁移中发现的
可复现问题须实际处理，并保留失败尝试。仅历史原因仍未知不是永久阻断发布的条件；
未处理的新验收失败仍是具体阻塞。

采集受到当前令牌、支持来源和配置范围约束。有限范围的 Degraded 不自动等于
失败，也不能被美化成完整覆盖。本产品不承诺完整软件足迹、最终文件归属、安全
删除、自动卸载或回滚；不自动提权、安装服务或启动常驻后台采集。
