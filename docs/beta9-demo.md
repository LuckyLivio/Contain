# Two-minute interview demonstration

1. **用户原来卡在哪里？（约 20 秒）**
   展示改版前页面：用户先拿到安装包，却必须提前猜软件将装到哪个目录；选错目录会漏掉范围外操作。
   指出这是原有后端范围筛选造成的限制，不能靠删掉必填提示解决。

2. **现在少做了哪一步？（约 25 秒）**
   在新页面选 EXE，保留“跟随安装器记录”，直接点“开始记录”，照常安装。
   用户少做了预先猜目录、选择观察范围这一步。需要前后状态对比时仍可选择手动目录方式。

3. **现场能拿哪条事件说明记录有效？（约 50 秒）**
   在本次保存的会话里搜索目标文件名，选中一条 High 的 `write_requested`，复制 ID 并打开解释：
   核对同一事件的 PID、进程创建时间、执行实例规则和完成依据，再重开会话查看同一条。
   工程复核样本为 `35da64dd-eba3-42c7-a060-1194cb98e5af`（安装器）和
   `4de44c60-230b-4490-98f0-c1cd0f22d70c`（直接子进程）；产品包实际验收与可选 7-Zip
   事件 ID 见 Release 的构建身份和独立试用结果。明确说明：这证明执行关联，不证明当前路径或最终归属；
   没有安装前基线，缺少写入者依据的记录继续显示 Unknown。

4. **哪些复用了开源，哪些属于本项目？（约 25 秒）**
   复用既有 WinForms、Rust/SQLite 和固定的 ferrisetw ETW 解析基础；布局阅读了微软 Fluent 2 公开指南，
   没有引入新 UI 框架、图标或运行时。Contain 自己完成事件准入边界、进程实例与直接子进程判断、
   损失处理、保存及解释、页面流程和独立夹具核验。7-Zip 只作外部试用软件，未把其代码当成本项目实现。
