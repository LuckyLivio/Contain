# Beta 6: export every matching event

After searching **事件与依据**, **导出全部 N 条匹配结果** writes all matches
from the current database and exact session UUID to one local HTML file. It
works from any result page, with or without a selected event. The query, page
and selected explanation stay in place after export, dialog cancellation or
failure. Loading, failed and empty searches cannot export stale prior results.
Ordinary browsing continues to use **导出本页报告** with its existing scope.

Search export uses one read-only CLI snapshot and the same matcher and ordering
as Beta 5. Its count and complete event sequence belong to that snapshot. A
fingerprint of the session identity/name, query and full ordered event content
must match the successful displayed search. Equal-count replacements are
detected; changed results require refreshing before export. Existing read
timeouts and output limits remain enforced, with an explicit failure rather
than a partial report labelled complete.

The report contains the session name/UUID, search text, scope, actual event count
and each original event's ID, time, operation, resource and confidence. It uses
escaped text, no scripts and no external resources. Unmatched events, other
same-name sessions and private diagnostic logs are excluded. Writing uses a
unique temporary file and a final non-overwriting move. Cancellation and failure
clean up that temporary file and preserve an existing target.

## Acceptance and download

The decisive fixture is the same isolated synthetic Beta 5 record: 130 events,
53 matches with fixed IDs `synthetic-search-event-070` through `-122`, plus a
different same-name session. Native acceptance operates the actual packaged
EXE from page two, selects event `120`, saves HTML, then extracts and compares
every event-row ID with that predetermined ordered list. It also checks the
retained page/selection/explanation, ordinary export and failure/cancel paths.

The [Beta 6 release](https://github.com/LuckyLivio/Contain/releases/tag/v0.3.2-beta.6)
provides the actual accepted Windows x64 ZIP, SHA-256, build identity and a
synthetic HTML report generated by the packaged desktop. The build identity
records exact source/CI, native Windows/DPI, counts and remaining limitations.
The accepted package is uploaded without rebuilding or repacking.

No new installation or ETW capture is needed for this saved-record feature.
Simulated scaling is separate from real monitor DPI transitions. Windows 10/11
manual trials, ARM64, Parallels and additional installer matrices are not newly
established. The existing [finalizing issue](https://github.com/LuckyLivio/Contain/issues/5)
remains separate. Matching events and confidence labels do not establish final
ownership or permission to delete.
