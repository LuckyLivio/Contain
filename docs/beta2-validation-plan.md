3. 同一 Windows runner 固定顺序 beta.1、候选、候选、beta.1（ABBA），
   每次同一独立夹具和12,000个背景文件写入/重命名/删除，零重试。
   保留四次实际回调/源记录量、所有来源/队列/候选/保存损失、父/子独立真值和无关负例。
   候选两次均需零来源/应用/候选损失、目标可靠身份及成功完成、无错误归因、成功保存精确会话。
   基线失败保留，不要求基线必须失败才允许交付诊断增强。
4. 最终 ZIP 在原生运行前冻结；实际 packaged WPF 检查同名 UUID、搜索/分页、
   解释/复制、本页/全部匹配导出及取消/覆盖、快速切换、外部只读、窗口/键盘和截图。
   一次受控安装通过安装器自己的界面更改新目录，Contain 保持默认跟随、未接收该目录；
   核验父/直接子变更独立真值与无关写入负例，保存、打开准确会话、解释、退出重开。
   夹具是独立操作真值；不将第三方安装或 process_start 冒充写入真值。
5. 源码或运行配置有必要改动后，记录新假设和新尝试；保留旧失败，不重跑挑绿色。
   真实 DPI 与模拟缩放分别记录。普通测试仅使用隔离的标记测试库。

B5 在冻结 ZIP 后先执行原定四次 ABBA，比较成功且确认四次所有自有进程已退出后，
再执行一次 WPF 交互安装验收。此前 B1/B2/B4 被 GUI 观测检查阻塞、B3 主动取消，
尚未取得 ETW 对照；此次仅调整阶段顺序，优先取得独立来源诊断。总计最多五次采集、
同机 12,000 背景文件、ABBA 顺序、输入、阈值和零重试均保持不变。来源比较失败时

## 本轮 B：一次接收积压窗口实验（独立调查，不是 A 的发布门）

A 的实际交付状态单独记录；本调查不修改 A 或历史 PR20，不宣称修复原 Parallels 会话。
唯一目标是定位首次明显积压／首次溢出前后，接收消费者实际处于哪个已测阶段。

- 基线源码固定为 `f76a8618426945093eacdd5751d49d2633635e78`：main 的旧采集行为和
  已单独审查的 SQLite 安全升级。基线将重新构建并应用相同观察补丁；**不是原 Release ZIP**。
- 候选行为基底固定为 `347a86ee730c4fd2d9ee775add60a6c5deddf7fa`，只追加本轮观察。
  候选保留 PR20 的行为差异；两侧差异文件与补丁 SHA 必须列入构建身份，不能据此孤立归因。
- 冻结候选 SHA、`347a86e..候选` 的公共观察补丁 SHA-256，以及本文件完整 SHA-256，
  三者作为显式 dispatch 输入。基线对同一补丁的三方应用有冲突、观察实现不一致、
  Cargo 清单或安全依赖锁不同，均在采集前失败并保留现场。
- 同一 Windows runner、同一实际 MSVC x64 工具链，两个核心均 debug 构建；记录实际
  Windows／系统与进程架构、工具版本、源码、有效补丁、锁文件和全部固定二进制哈希。
  两侧统一 `-Profile`、`CONTAIN_PROFILE_BACKLOG=1`、`CONTAIN_PROFILE_THREAD_CPU=1`。
- 采集前，两侧实际运行同一 receiver profiling 不变性测试与固定容量窗口可靠性测试；
  同一观察模块已完成的 Linux 固定工作量离线成本实验保留全部 18 样本和 3 次预热，
  工作流按 `input_sha256` 核验其八项实际输入精确等价，不重复成本 campaign。输入变化须
  先说明新假设及重新测量依据，不能继承旧结果。上述任一未通过，不启动真实采集。
  离线输入／耗时不是 ETW 开销或消费速度保证；离线 CPU profiling 关闭的范围单独标注。
  所有 live 前候选侧另执行仓库必需的 `quality.ps1 -Mode Bench` 原固定 20,000 work、
  七样本及原断言；这是既有纯内存质量门，不是重复 profile 成本 campaign，也不是 ETW。
  Bench gate 失败即停止；安全报告保留全部数值样本，不公开路径或原始日志。
- 一轮 ABBA，严格顺序为 `r1/baseline → r1/candidate → r2/candidate → r2/baseline`，
  最多四次采集、零重试。每次复用既有独立父写入／直接子写入／无关写入夹具，固定
  12,000 个背景文件的写入／重命名／删除，共 36,000 次独立核验的成功操作。
- 不调整接收队列 4,096、候选 2,048 条／8 MiB、64 MiB journal、settle 1,500ms、
  最大收尾 10,000ms，不改变 provider、范围过滤、身份、归因或完成关联规则。
- 观察阈值为 1,024 条；首次标记是成功投递后发布的 entering 时占用估计越阈，
  不是实际队列占用精确越阈的时刻。每个窗口最多保留 64 个前置完成阶段、触发观察及 64 个后置
  完成阶段，即 `64+1+64=129` 条。保留首次 producer 单调时刻、receiver 观察时刻、
  检测延迟、队列及候选计数、阶段墙钟与可用线程 CPU、上下文缺失与遗漏数量。
  嵌套阶段不相加；排队延迟不是线程暂停；缺失 CPU 不写成零。
- 原严格零损失 oracle 结果原样保留。EventLoss 后正确降为 Unknown 可以仍是有效测量，
  不能伪称通过该 oracle；目标错误归因、无关误升级、负例不明、工作量不完整、准确会话
  保存／冷读失败、守恒不符、观察结构失效或上一轮自有进程未退出时停止后续样本。
- 只发布白名单数值和固定阶段标签。完整 profile、路径、真值、数据库与原始错误保持私有；
  固定构建且尚未接触用户数据的诊断二进制及代码补丁可独立保留供核对，明确不可当作 A 发行包。

窗口创建会分配／克隆最多 64 条前置记录，follow checkpoint 在既有 live 锁内；
span 结束计时及 CPU 读取先于该 recorder 工作，因此自开销可能落入间隙或外层阶段。
已测 Linux CPU-off 成本不覆盖 producer 回调与 Windows live 锁；不能把 wall−CPU
差值称为线程暂停，也不保证这些观测对原生调度没有影响。

本轮只交付三种结论之一：

1. **复现并取得有效窗口**：给出最可疑阶段、支持与排除证据及一个最小后续修复假设；
2. **未复现**：给出最大积压上下文与阶段分布，明确本轮未复现，停止追加采集；
3. **测量或测试失效**：保留失败与未执行项，说明缺失内容，不偷偷重跑替换结果。

短前／后窗口、CPU 缺失和不可分类间隙必须原样说明。首次积压或首次溢出触发点未被
任何保留的完成阶段覆盖时，保留该窗口与全部统计，但将测量判为失效并停止后续采集，
明确可能早于 receiver 启动而缺少阶段上下文；不称为取得有效因果窗口。这些
观测边界不能被包装为已定位具体暂停原因。一次 ABBA 全通过也不证明原机问题已修复。
本调查完成后不自动合并、不发 Release，也不继续扩展产品修复；产品修改需另定范围和验收。
